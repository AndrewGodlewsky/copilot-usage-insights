# Usage feedback implementation

Three independent releases follow the user reports, in this order. The user authorized implementation and releases without further design discussion.

1. **Effort and model switching:** retain request-level effort, aggregate charges within each model/effort pair, and show explicit real changes in Efficiency → Worth a closer look → Model and effort changes. Keep missing effort unknown, exclude no-op and child events, distinguish manual selections, and avoid inferring causality or switches from parallel request order. Track cross-tab UX, before/after comparisons, startup settings, and VS Code verification in a GitHub issue.
2. **Skill activity coverage:** separate recorded CLI activation/failure counts from the availability of billing receipts. Include otherwise-unattributed activity with visible attribution counts; retain exclusions for conflicting/non-Copilot evidence. Do not create credits from summaries. Assess VS Code's “Reading skill” signal as load evidence, not proof of successful activation; never count arbitrary SKILL.md reads as use.
3. **Prompt delivery:** separate human delivery classification from complete single-prompt billing attribution. Use omitted-source journal fixtures, exclude automation/subagent messages, give delivery its own denominators in UI and AI review, and preserve prompt-credit and depth calculations.

Each release requires focused synthetic regression tests, a full build/test run, synchronized manifests, bundled release notes, and a separate commit pushed to main. No installed-plugin edits or browser automation. Personal logs and report-specific identities are not committed.

Broader effort/model rollout: https://github.com/AndrewGodlewsky/copilot-usage-insights/issues/2

## Skill coverage decision

Saved CLI activations and explicit failed loads now count even when billing receipts are absent. Included unverified activity and excluded conflicting-provider activity have separate visible counts; no charges are inferred. Date, project, session and environment filtering remain event-based, while skills continue to ignore the model filter.

VS Code skill import remains a disclosed limitation. The upstream [read-file tool](https://github.com/microsoft/vscode-copilot-chat/blob/main/src/extension/tools/node/readFileTool.tsx) prepares the localized “Reading skill” message before execution; this alone cannot prove a successful load. Its [chat session operation log](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/chat/common/model/chatSessionOperationLog.ts) also requires replay-aware reconstruction. A future importer should establish completion, timestamps and stable identities with synthetic fixtures, distinguish attempt/read/activation, and avoid retaining transcript or file content. The report explicitly permits disclosing this limitation instead of guessing activations.
