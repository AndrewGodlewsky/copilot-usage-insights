# Token explorer measurements

Implementation based on v0.1.68's existing receipts, activity, prompt links, and explicit context snapshot. No new log source, background recorder, model call, or automatic context inspection.

| Section | Useful view | Evidence boundary |
| --- | --- | --- |
| Overview | Input/output balance, request averages, coverage; token mix on calls with an output count and a complete cache split; largest model, project and five largest conversations by measured token share; input and credits per call by period; an index of the other sections with one headline figure each | Token volume is not cost share or task value. Each token is counted once in the mix; a large share can simply be where most of the work happened. Sections that need a context snapshot say so instead of showing zero |
| Always-loaded context | Room left against the reported allowance; what fills the context by category; instructions/definitions versus conversation; attributed sources grouped by kind with what can be changed; snapshot tool definitions beside the history average; a labelled illustration of setup carried across the calls behind one prompt | Current hosting conversation only; not historical or necessarily loaded on every call. Sources overlap and are not summed. The illustration multiplies one snapshot by a history average and is not a measurement |
| Tool and MCP footprint | Tool-definition tokens per call and input share, by period, by group of available-tool counts, by project (at least 20 measured calls) and by model; available tools per call beside different tools executed; current attributed definitions | Definitions are part of input; available tools (per call) differ from executed tools (whole history) and unused is not waste; no cache split by content; project and tool-count gaps can come from model or task |
| Files, searches, and tool results | Conversation/context volume, tool-attributed sources, top executed tools | Conversation includes user/assistant/tool messages; no historical per-file or per-result token bill |
| Cache reuse | Matched uncached input, cache reads and writes; per-model reuse; read share by time since the previous main-conversation call (under 5, 5 to 60, over 60 minutes), on the first call in range and after a model change; trend; conversations with the most input not read from cache | Missing cache detail is not zero; no inferred cause or savings. Main-conversation calls only, because subagent calls cannot be ordered; lower reuse after a pause is consistent with an expired cache but the cause is not recorded |
| Skills and instruction footprint | Recorded uses split by how each was loaded (preloaded at start, invoked by the agent, invoked by you, not recorded), per-skill conversations, projects, last use and failed loads; current custom and system instruction tokens with skill and plugin sources | Sources overlap; use counts do not measure tokens or prove skill value. Skill activity retains its existing model-filter exception. Snapshot sources are never joined to recorded uses by name. Conversations with model calls are shown for scale only, not as a matched denominator |
| Work behind each prompt | Typical (median) and average calls, tokens and credits per eligible prompt; prompts grouped by call count with each group's credit share; credits held by the heaviest tenth and the fewest prompts holding half; linked calls split into started by the message, agent continuations and subagent calls; five heaviest prompts by complete charge; exclusions | Reuse whole-prompt eligibility and submission-date semantics; model filters are contributions only. A heavy prompt is often a large task; no prompt text is read or shown. Subagent work means a recorded parent tool link, nothing inferred from timing |
| Delegated work | Shares of calls, tokens and credits by initiator; subagent against main-conversation calls per call (input, output, credits, cache-read share, duration); model routing; conversations with the most subagent calls; subagent share by period | Unknown initiators stay unknown; no guessed parent attribution or quality assessment. A lower per-call figure is not a saving |
| Reasoning and generated output | Output totals, matched reasoning share and remaining output, model comparisons; trends; calls grouped by output size; effort levels within one model (30 or more matched calls each); output per second of whole call time | Reasoning is a subset of output; subtract only on the same valid measured calls. Unknown effort is not a level; calls at each level were different work; speed includes the wait for the first token |
| Biggest spend drivers | Top sessions, recorded credit shares and coverage; groups making up half and 80% of credits; each top group's calls and credits per call as multiples of the median group; top projects, models and days | Partial charges can change ranking; expensive does not mean wasteful. Multiples describe size, not a cause |

Every view should offer an evidence-led observation and one concrete experiment with a measurement to compare. Lists are bounded, labels wrap, zero/missing/partial values remain distinct, and existing number/theme/text-size settings apply. Keep the current navigation and dedicated Overview, Context, and Cache panels. Leave Worth a closer look and AI Review behavior unchanged.

Context category and entry semantics were checked against the installed Copilot SDK `generated/rpc.d.ts`, `SessionContextAttribution`: `systemPrompt` excludes custom instructions, `systemTools` excludes MCP definitions, and `messages` includes user/assistant/tool messages. Entry kinds are open-ended (`skill`, `subagent`, `mcpServer`, `tool`, `system`, `toolDefinition`, `plugin`); labels are presentation-only and must not be used to infer source identity. Entries can overlap through parent relationships. Do not sum them.

Validation: synthetic matched/missing/zero metrics; prompt eligibility, replay, subagents and date/model boundaries; context kind filtering and escaping; all ten sections with empty and populated data; navigation and refresh preserve selection, focus and snapshots without extra network calls; build and full suite before release. In-app visual testing remains manual.

Implemented in v0.1.69. `npm run build` and all 260 tests pass, including matched/zero/missing measurements, prompt linking and filtering, sparse delegated-call coverage, escaping, all ten sections, snapshot reuse, and focus restoration. Independent review corrected MCP-source wording and added independent sample coverage to delegated model averages. No browser or desktop automation, paid calls, or live context inspection was performed; narrow-panel layout, large text, and visual balance need a manual check in Copilot.
