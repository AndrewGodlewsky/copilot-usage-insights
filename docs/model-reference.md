# Copilot model reference for AI review

This feature adds captured Copilot model identities, availability and capabilities to the review prompt. It does **not** replace recorded credits with calculated prices. No runtime pricing website, provider API or benchmark API is contacted. An explicit **Create AI review**, **Refresh models**, or **Reconnect** action uses the existing attached Copilot host.

## Contract verified on 2026-11-16

Static inspection used the installed desktop SDK `1.0.106-8.unstable.r43566476370.g869eef3`, its `extension.js`, `extension.d.ts`, `types.d.ts` and `generated/rpc.d.ts`. No live model request or personal history was used for verification.

The extension joins a `CopilotSession`. Its generated `session.rpc.model.list({ refresh: true })` sends **`session.model.list`**, returning `{ list: JsonValue[], ... }`. That list can mix Copilot and BYOK entries. It is **not** the typed server-level `models.list` response. We accept only the explicitly supported nested fields; unfamiliar shapes remain unknown. The public [SDK types](https://github.com/github/copilot-sdk/blob/main/nodejs/src/types.ts) and [generated RPC contract](https://github.com/github/copilot-sdk/blob/main/nodejs/src/generated/rpc.ts) were checked against the installed declarations.

Supported metadata: exact `id`; `provider.kind = copilot`; `policy.state`; boolean `capabilities.supports.vision`, `reasoningEffort`, `thinking`, `toolCalls`; the enumerated `adaptive_thinking` support; positive integer `max_prompt_tokens`, `max_output_tokens`, `max_context_window_tokens`; allowlisted `supportedReasoningEfforts` and `defaultReasoningEffort`. Invalid or absent capabilities/limits become null. Limits above 100 million or prompt/output limits exceeding the stated context limit are rejected. Unknown policy states are not eligible alternatives. An omitted policy retains the existing older-SDK eligibility rule, labelled `unspecified`.

### Pricing units and limitations

The SDK has a **separate server RPC**, `models.listTokenPriceUnits`, returning `{ units: [{ modelId, unit }] }`. Its enum is `ai_credits` (no conversion) or `nano_aiu` (divide by 1,000,000,000). The joined session exposes no supported public route to this server RPC. This implementation does not reach into private transport fields or create a helper just to obtain prices. Consequently, the installed-host path labels present token prices **unsupported: price-unit-unavailable**, and does not export ambiguous numeric rates. Absent prices are **missing**, not zero. Actual host payloads remain unverified until an authorized live-host check.

The normalization seam supports the typed unit response with synthetic fixtures, ready for a future supported host route. It accepts `billing.tokenPrices` fields `inputPrice`, `outputPrice`, `cacheReadPrice` (legacy `cachePrice` fallback), `cacheWritePrice`, `cacheWrite1hPrice`, positive integer `batchSize`, default `maxPromptTokens` (legacy `contextMax` fallback), and `longContext` with the same rate fields and its own prompt budget. Rates must be finite nonnegative numbers. Zero stays zero; absent categories stay null. All five rates present yields `available`; otherwise the section is `partial`. Invalid rates/budgets reject the pricing section while preserving the model's usable capabilities. Two tiers require positive, increasing budgets; contradictory old/new budget fields are rejected. Promotions/auto discounts remain an unsupported billing regime. Legacy request multipliers stay separate and are never multiplied into token rates.

SDK prompt budgets are retained **as budgets**, not asserted to be exact billing thresholds. The [GitHub billing reference](https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing) distinguishes pricing tiers by input thresholds and lists USD prices per million tokens, but that does not establish the units of an untyped session response. It also mentions cache-write charges without establishing a universal replacement-versus-supplement formula for every SDK category. Both `tierSelection` and `cacheWriteSemantics` therefore stay `unverified` here.

There is deliberately no same-volume estimate. Future estimates need verified tier boundaries and cache-write semantics plus compatible **per-request** measurements, including cache duration when relevant. Input already includes cache; reasoning is already in output. Neither may be added again. Never infer a tier from an average, combine measurements with different denominators, or treat current rates as a historical bill. Model changes may alter tokenization, reasoning, retries and cache reuse. Pricing alone is not evidence of task success or model suitability.

## Normalized schema and privacy

Both builders support the shared envelope:

```js
buildEfficiencyReview(report, context, scope = {}, modelReference = {})
// serialized snapshot:
modelReference: { schemaVersion: 1, catalog: null, benchmarks: null }
```

The card-review builder also accepts the reference as its optional fifth argument. Three-argument legacy panel-builder calls continue to work. Each historical model retains its `Model N` alias and gains nullable `modelId`. Identity requires every record in the display group to have the same **raw** ID, an exact match in the public identity allowlist, and an unambiguous Copilot catalog entry or a reviewed bundled public-alias mapping. A missing ID, mixed-ID group, suffix, label-only match, BYOK entry or unknown/private alias is insufficient.

`src/core/public-models.mjs` owns the identity registry; `src/core/model-reference.mjs` owns catalog normalization. Historical GPT-4.1, GPT-5 and Sonnet 4 identifiers are documented in the [benchmark source record](research/2026-11-16-model-benchmark-sources.md). Public IDs were cross-checked against GitHub's [Copilot model inventory](https://github.com/github/gh-aw/issues/52187), the `github-copilot` entries in its [model data](https://github.com/github/gh-aw/blob/main/pkg/cli/data/models.json), and [public model labels](https://docs.github.com/en/copilot/reference/ai-models/supported-models). No prices from those development references are bundled. Add future identities only after verifying their exact public Copilot IDs; never add a prefix/suffix guessing rule. The allowlist is intentionally incomplete and does not establish current account availability.

Catalog schema 1 contains `source`, UTC `capturedAt`, `freshness`, `priceUnitSource`, bounded `models`, `coverage`, `omitted` and `estimates`. Each model has a canonical public label, eligibility, supported capabilities, limits, reasoning options, explicit missing fields, separate request multiplier and pricing status. Aliases are never replaced with arbitrary SDK names. Account names, endpoint URLs, policy terms, descriptions, credentials, prompts, paths, project/session names and MCP names are not reference fields. Duplicate IDs are omitted entirely instead of choosing a winner.

Selection is deterministic: at most 20 relevant historical identities, then at most four eligible alternatives, prioritizing selected bundled-evidence candidates and sorting each group by exact ID, without a cheapest/best ranking. The card-review evidence uses six historical groups. Omission counts distinguish unverified IDs, wrong providers, duplicates and selection limits. Counts of identified historical groups and capture time are visible alongside the prepared review; the full selected reference is in the copyable prompt.

`benchmarks` is independent and supplied by the local, validated dataset. See [bundled model benchmark evidence](model-benchmarks.md) for its schema, sources, conservative identity/configuration mapping, offline packaging and maintenance procedure. The complete provenance section replaces the earlier placeholder fixture contract. SDK unavailability does not erase a valid bundled section.

## Preparation, freshness and send

The catalog cache belongs to one canvas service, lives in memory for up to five minutes, and checks the current account before reuse. Concurrent catalog readers share one operation; cancelling one reader does not cancel remaining readers. The last reader's cancellation aborts ownership, and late results cannot populate the cache. Explicit Refresh models/Reconnect bypasses the cache. Identity changes, failed refreshes and failed send-time reference validation invalidate it. No catalog request or helper is started by normal usage refreshes, filtering or rendering. Reads have a 15-second overall wait; older SDKs and failures leave local benchmark context and statistics-only review usable, with catalog availability labelled unknown.

Preparation captures the selected history/filter/time and already-inspected context, then builds the full first-pass prompt with bundled guidance, model-reference instructions, allowlisted statistics and the saved excerpt policy. The preview textarea and **Copy review prompt** contain that exact text; the helper sends it unchanged. Metadata is not appended at send time. The SDK system instructions and response schema remain separate protocol fields, as before. Optional targeted excerpts remain a disclosed second pass, never part of the statistics-only first pass.

Preparation is discarded after cancellation or a newer preparation. Settings changes during preparation, or model/reasoning/excerpt-policy changes before analysis, require preparing again. The internal catalog token is not part of the exported prompt. Before inference, the helper verifies the current parent catalog against that captured reference and checks the prepared account, while retaining existing provider, policy, model, tools, workspace and parent/helper account checks. A changed public capability/availability snapshot or explicit refresh requires re-preparation. No automatic model substitution, inference retry or settings change is introduced. Statistics-only fallback still performs all live isolation and eligibility checks before inference.

The complete first-pass prompt plus response schema is limited to 46 KiB UTF-8, leaving space for system instructions under the existing 48 KiB send guard. The send guard applies to both passes. Entry selection is deterministic; if needed, complete catalog entries are removed from the tail, then bundled entries, with explicit omission counts and corresponding identities removed. JSON is never sliced. If the base statistics still cannot fit, preparation fails before sending. UI text uses the existing textarea/textContent and escaped card rendering.

## Scale and verification

Identity tracking adds one nullable field per display-model accumulator, in the existing pass over loaded records. It retains no ID set per record, rereads no journals and adds no history-sized pass. A Windows/Node v24.22.1 synthetic benchmark with 100,000 records, four models and 1,000 sessions measured median accumulator time over eight warmed, alternating runs: **32.60 ms at base 7579014; 35.18 ms with identity tracking** (about 2.58 ms additional on this machine). This measures the affected accumulator, not full dashboard loading or live SDK latency.

Regression fixtures cover units/zero/malformed pricing, tier budget ordering, provider/policy/duplicate exclusion, raw-ID ambiguity, retained privacy sentinels, independent benchmark data, deterministic UTF-8 bounds, account changes, cache/coalescing/timeout/recovery, preparation cancellation/settings races, exact preview/send equality and unchanged recorded totals at 100,000 records. The custom flattening build includes the shared module and packaging tests parse the generated panel.

Still requiring explicit authorization: verify actual model-list shapes, availability and reasoning options against a live attached host/account, and manually check the reference notice and copy action in the plugin. Tests use fixtures only; they do not demonstrate live pricing availability, account verification or a successful paid review.
